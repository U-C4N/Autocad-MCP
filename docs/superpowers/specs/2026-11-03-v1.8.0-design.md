## 1. Summary

1.7.0 made what the server draws provable. 1.8.0 makes the server **remember what it did
after its process dies** (B13 durable journal, save-anchored checkpoints, cross-process
lineage) and **finish a job in one call** (set-based edits, `dimension_auto` v2, atomic
`cad_batch`). It closes, one by one, the behavioural claims AgentCAD published against us:
H1 0/3 over five revision rounds, no undo after a restart, a failed batch whose first step
stayed applied, 124/89 calls on H4/H5, a wrong "by-layer" report under the full catalog
(§4.5), a circle landing in paper space, 16 LISP refusals and untyped errors (§4.6). It
answers the rubric deductions (§4.7): C2 (the value a dimension shows versus the geometry),
S1 (read-only and operation scopes, a write-extension policy, HTTP Origin/Host/body limits),
T3 (a token budget in CI and a cross-version perf comparison). It delivers the promised
1.8.0 items — B24–B28 `mech_part_revise` (new), obstacle-aware P&ID routing, a read-only
multi-sheet P&ID project, B40 (the tables a licensed copy exists for), F08 (the read tier)
— and moves the .NET worker to 1.9.0 with a measured ADR. The token goal is measured
against ceilings fixed in advance: default discovery catalog 503 → ≤ 250 tokens, H4 layer
cleanup ≤ 3 calls, H5 part dimensioning ≤ 2 calls, H1 "the value in round 2" ≤ 2 calls.

## 3. Execution model

- **Release worktree:** `C:\Users\ASUS\Documents\GitHub\Autocad-MCP-v180` on branch
  `release/1.8.0` (HEAD = the `v1.7.0` tree, `58a05dd`). Everything lands there.
- **Parallel tasks:** each runs in its own worktree `..\Autocad-MCP-v180-<task>` on branch
  `v180/<task>`, created from `release/1.8.0`, and is merged back by the coordinator.
  Merging into `main`, tagging and pushing are the maintainer's.
- **The main checkout (`..\Autocad-MCP`) is never touched.**
- **git** is not on PATH on this machine; use
  `C:\Users\ASUS\AppData\Local\GitHubDesktop\app-3.6.10\resources\app\git\cmd\git.exe`.
  Scripts that shell out to a bare `git` (`benchmarks/compare_versions.py`,
  `benchmarks/perf_compare.py`, `benchmarks/run_competitors.py`) need that directory
  prepended to `PATH` for the process.
- **Python** is a uv-managed 3.12; uv is installed into the system Python 3.15 via pip, so
  the command is `python -m uv` — every run is `python -m uv run --frozen …`
  (`--all-extras` once in a fresh worktree). Never `uv sync`; `uv lock` only in 1.8-25's
  version bump.
- **pytest** always with `-p no:cacheprovider --basetemp=out/pytest/<key>` (`out/` is
  git-ignored).
- **TDD:** failing test first, then the code; never delete, skip or weaken a test; a test
  that asserts what the real API cannot do is fixed to the measured truth and recorded.
- **Commits:** `git -c user.name="Umut CAN" -c user.email="umutcan.edizaslan@gmail.com" commit`,
  message ending with `Co-Authored-By: <the Claude model that wrote it> <noreply@anthropic.com>`.
- **Live AutoCAD:** AutoCAD 2026 is the only live seat and is **not running now**. Live
  steps are scheduled at the end of each phase (W1 additionally runs the S4/S5 probes) and
  need the maintainer to open it. Attach with `GetActiveObject` only; a probe holds its own
  `Documents.Add()` document and closes it with `Close(False)` in a `finally:`;
  `RPC_E_CALL_REJECTED` (-2147418111) is contention — retry with backoff up to ~90 s; code
  that drives `ComBackend` against the seat runs only at a phase's foundation/final stage,
  never in a parallel group. Every new ActiveX member is measured on AutoCAD 2026 first;
  the 1.7.0 COM pitfalls list stays binding. Live results go through `scripts/live/harness.py`
  into `benchmarks/results/live/`.
- **Client drawings never enter the repository** (§10).
- **A red phase gate stops the run.**
- **Reviews:** one high-effort adversarial review (at most three verified findings, one
  fix round) on 1.8-02, 1.8-03, 1.8-08, 1.8-09, 1.8-15, 1.8-19 and on the last group of each
  phase.
- **Known red inside a task:** `tests/test_release_consistency.py::test_document_numbers_match_the_tree`
  drifts on README's test count whenever a task adds tests; the task deselects exactly that
  test and says so; each phase's last task retakes the figure and leaves it green.

## 10. Confidentiality

No client drawing, file name, client or site name, tag or quantity from the maintainer's
archive enters the repository, a fixture, a benchmark result, an eval case or a commit
message. Every fixture is synthetic and generated (the messy-layers fixture, `lying_dims`,
the three P&ID sheets, the flange). The journal's argument text lives only in STATE_DIR —
outside the repository and the drawing's folder, refused at startup otherwise —, bounded by
`JOURNAL_ARGS` (`digest` keeps no argument text); `fault_inject.py` and the durability tests
use temporary STATE_DIRs. B40 publishes only dimension values, from a licensed copy, never
from a secondary catalogue. Live results go through `scripts/live/harness.py`'s `scrub`.
