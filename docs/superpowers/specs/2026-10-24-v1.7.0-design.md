# AutoCAD MCP Pro v1.7.0 — safe execution and measured acceptance

**Date:** 2026-10-24 · **Status:** implemented as 1.7.0 on `release/1.7.0` (2026-10-25,
three gated phases; merging, tagging and publishing are the maintainer's) · **Parent:** the maintainer's roadmap `plan.md` (local, Turkish) and
the 2026-10-24 review of it · **Baseline:** `main` = tag `v1.6.0` (`cdb1063`): 247
tools, 8 resources, 5 prompts, 28 groups; 4991 tests pass (1 xfail) with a
writable `--basetemp`.

## 1. Summary

1.6 taught the server to draw whole sheets and to read other people's drawings.
1.7.0 makes what it draws **provable** and what it runs **safe**:

- a source requirement ("Ø40 bore, 6 holes on a Ø120 circle") is bound to the real
  CAD feature, measured on the geometry — not on a label, a stored model or the
  numbers that were typed in — and measured again on the saved file after it is
  reopened, with a pass / fail / unknown verdict per requirement and the evidence
  behind it;
- a cancelled call, a big drawing or a hostile text cell can no longer produce a
  silent wrong answer.

Findings that shape it, all reproduced on the maintainer's machine on 2026-10-24:

1. **Cancelling a call releases the document while its worker still writes.**
   `EzdxfBackend._async` releases the lock in `except BaseException` when the
   awaiting task is cancelled; `asyncio.to_thread` cannot stop the thread. A
   second call then runs against the same `Drawing` concurrently — reproduced
   with `EZDXF_CALL_TIMEOUT` both 120 and 0, no quarantine. The MCP SDK cancels a
   request by cancelling an anyio scope, so a client pressing Esc is enough.
2. **QA reads stop early and fail open.** Four critique checks read
   `entity_list(limit=5000)` (`construction_left`, `untrimmed_corner`,
   `duplicate_entities`, `dim_overlap`), the validator reads 10,000; a
   construction line at position 5,001 and a duplicate pair after 5,000 lines
   both report zero issues. Every check ends in `except Exception: return []`, so
   a check that crashes reads as clean. `untrimmed_corner` and `dim_overlap` are
   O(n²) and run on the event loop: 8.9 s at 5,000 lines, during which the server
   answers nothing, not even a cancel. `entity_list` reads only the current space.
3. **Exported text becomes a formula.** `=1+1` from a drawing stays `=1+1` in the
   P&ID CSV and is stored as a formula cell (`data_type='f'`) in the BOM XLSX; the
   takeoff workbook has the same path.
4. **"Delivered" is not "measured".** `drawing_deliver`'s reopen parity compares
   counts, types, layers and extents of the current space; a hole moved inside
   the outline passes. On COM the delivery DXF is written with `SaveAs(path, 61)`,
   which re-points the open document at the DXF. `drawing_finalize` never reopens.
5. **Nothing links a requirement to geometry.** `drawing_preflight` checks only
   that `units`, `part_type`, `dimensions` and `tolerance_policy` are present; a
   DIMENSION exposes only `defpoint` / `text_position`; a machine part records no
   feature → entity link; `PlanSpec` lives in memory only.
6. **COM writes to whatever document is active.** `_acad_doc()` re-reads
   `ActiveDocument` on every call; `_ensure_document_state` resets metadata when it
   changes and never refuses; `transaction_rollback` sends `_UNDO _B` to the
   document active at that moment.
7. **The premium skill is gone.** Added in `9258da4`, deleted in `0c7f64c`
   (2026-06-18); a comment in `server.py` and the maintainer's uncommitted pre-work
   still point at `.claude/skills/autocad-mcp-premium/`.

## 3. Execution model

- **Branch:** everything lands on `release/1.7.0`, checked out in the sibling
  worktree `..\Autocad-MCP-v170`. `main` and the primary checkout are not touched.
  Merging into `main`, tagging and pushing are the maintainer's decisions.
- **One workflow, three phases**, each ending in a gate (§8.4); a red gate stops
  the run. W1: Task 0 (triage) → draft + reconcile (Tasks 1, 2, 4) → groups →
  merge → Task 8 → gate. W2: draft + reconcile (Tasks 9–17) → foundation
  9 → 10 → 11 → groups → merge → 16 → 17 → gate. W3: groups → merge → 22 → 23 →
  gate (W3's tasks are implemented from this spec and their plan briefs, without a
  drafting stage).
- **Reviews:** one adversarial review at high effort with at most three verified
  blocking findings and one self-verified fix round, on Task 1, Task 2, Task 9,
  Task 12, group B (Tasks 13–15, one review of the group) and the W2 final
  (Tasks 16–17, one review).
- **Conventions carried from 1.6** (binding on every task): `uv run --frozen`
  (`--all-extras` once in a fresh worktree); pytest with
  `--basetemp=out/pytest/<key>` — the default `%TEMP%\pytest-of-VECTOR` is not
  writable on this machine (WinError 5 at setup); TDD; commits as
  `git -c user.name="Umut CAN" -c user.email="umutcan.edizaslan@gmail.com" commit`
  ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; the COM
  pitfalls list; every new ActiveX member measured on the running AutoCAD 2026
  first; registration gates (inventory, registry snapshot, aliases, packs, banner
  counts, README snapshot); never weaken a test; client drawings never enter the
  repository.
- **Known red inside a task:** `tests/test_release_consistency.py::test_document_numbers_match_the_tree`
  drifts on README's collected-tests figure whenever a task adds tests; a task
  deselects exactly that test and says so. Each phase's final task (8, 17, 23)
  retakes the figure and must leave it green.
- **Live AutoCAD:** one AutoCAD 2026 instance stays open for the whole run.
  Agents attach with `GetActiveObject` and never `Dispatch`. A probe holds its own
  `Document` object from `Documents.Add()` and never goes through
  `ActiveDocument` (a sibling's `Documents.Add()` changes the active document);
  it closes what it opened with `Close(False)` in a `finally:`.
  `RPC_E_CALL_REJECTED` (-2147418111) is contention: retry with backoff up to
  ~90 s. Code that drives `ComBackend` itself against the live seat (not a raw
  probe) runs only in foundation and final stages, never in parallel groups.

### Task 1 — cancel-safe execution (B01)

A call has one lifecycle whatever ends the wait — a deadline, a cancellation, a
shutdown — and the lease on the document follows the **worker thread**, never the
awaiting coroutine.

- **Cancelled while queued:** nothing was acquired; the cancellation propagates;
  no other call's lock is touched (today's behaviour, kept and tested).
- **Cancelled while running:** the lock is **not** released by the cancelled
  coroutine. Ownership passes to the worker: `AbandonedCall` gains a one-shot
  `on_finish` hook, set under a small lock so the race with the worker finishing
  is closed (if it already finished, release at once; never release twice). The
  hook releases the lock through `loop.call_soon_threadsafe`. The call is recorded
  (`call_outcomes`, below) as `cancelled_running`. If the worker is still alive at
  the call's **original deadline**, the existing abandon path runs at that moment
  (swap the lock, quarantine the document, cause `cancelled_then_deadline`); a
  pending deadline timer is cancelled when the worker finishes and in
  `disconnect()`.
- **Deadline overrun:** unchanged in meaning, but the branch must discriminate
  with `call.done()`, not `call.cancelled()` — the current test
  (`if call is None or not call.cancelled(): lock.release(); raise`) would release
  a still-running worker's lock as soon as the await is shielded. Waiters already
  past the quarantine gate must not inherit the orphaned lock after a swap (keep
  today's never-release rule for the orphaned lock, or re-check the quarantine
  after acquiring).
- **Read-only calls** (`_async(..., readonly=True)`: snapshots, lists, gets) that
  overrun keep their lease until they finish and answer "busy" to waiters — they
  never quarantine a document, because they cannot corrupt it. Every QA and
  verification read uses this flag.
- **`EZDXF_CALL_TIMEOUT=0`:** the lease is held until the worker ends; nothing is
  ever quarantined. Said in the config docstring and README.
- **The document a call ran against** is captured when it starts (identity and
  path), not read again when it is recorded.
- **Shutdown:** the lifespan's `finally` calls `backend.disconnect()` (and copes
  with `_make_backend` having failed). `disconnect()` waits a bounded time
  (`SHUTDOWN_GRACE`, default 5 s) for an in-flight worker, then reports it in the
  log; the server process still exits (the worker pool must not block interpreter
  exit — an explicit executor whose threads are not joined at exit, or an
  equivalent measured policy).
- **Rollbacks under cancellation:** `cad_batch`'s rollback and commit run inside
  `anyio.CancelScope(shield=True)` — the pattern `engineering/pid/spec.py`,
  `engineering/arch/spec.py` and `engineering/mech/draw.py` already use; an
  `asyncio.shield` does not survive anyio's level-triggered re-cancellation.
  `drawing_refine` rolls back on `BaseException`, shielded the same way. With the
  lease rule above, a shielded rollback waits for the orphaned worker instead of
  racing it.
- **COM:** a cancelled `_run` already cannot overlap (one STA thread, FIFO);
  Task 1 records the outcome (`cancelled_queued` / `cancelled_running`) so Task 10
  can report `unknown_commit`.
- **`call_outcomes`:** both backends keep a bounded deque of
  `{call, outcome, started, ended, document}` for cancellations and abandonments;
  `system_status` reports the last few. Task 10 builds on it.
- **`AuditMiddleware`** logs a cancelled call (`TOOL CANCELLED`) — it catches
  `Exception` today, so a cancellation is not logged at all.
- **Performance:** the fix must not make 1.6.0 slower. New
  `benchmarks/perf_compare.py --base v1.6.0`: builds a `git worktree` of the base
  ref, runs `benchmarks/perf_suite.py`'s workloads on both trees alternately with
  5 warm-up and 20 measured rounds, plus an **A/A calibration** (base against
  itself) to measure noise, plus one **server-level workload** (2,000
  `entity_create_line` calls through an in-memory FastMCP client, so middleware
  cost is measured — `perf_suite` drives the backend directly). Gate: the median
  ratio new/base on every workload ≤ 1 + max(0.05, 2 × A/A spread); the JSON
  report records both.

### Task 2 — complete QA scans (B02)

- **One read per run.** `run_critique(backend, focus, shared=None)` and
  `DrawingValidator.run(..., shared=None)` take an optional shared dict; the first
  check that needs entities takes one all-spaces snapshot (`take_snapshot`:
  in-memory on ezdxf with `readonly=True`, `Document.Export` on COM) into
  `shared["qa_snapshot"]`. `drawing_finalize` and `drawing_deliver` pass one dict
  to the validator, the critique and the topology focuses, so a finalize costs one
  read (one export on COM), not three.
- **Base checks** (`construction_left`, `untrimmed_corner`, `duplicate_entities`,
  `dim_overlap`) and validator steps 1–2 read the snapshot's records: every space,
  every entity, no cap. Pair checks compare only records of the same `space`.
  `untrimmed_corner` and `dim_overlap` use a grid hash (cell = the tolerance) and
  run their arithmetic in `asyncio.to_thread`. `duplicate_entities` is already a
  dict pass; it only gains the space bucket.
- **Failures are findings, never silence.** `run_critique` wraps each check: a
  `DocumentQuarantineError` propagates; any other exception becomes
  `Issue(severity="error", focus=<that check's focus>, message=…, detail={"code": "check_failed", "error": …})`.
  A read that could not complete becomes `detail.code = "scan_incomplete"` with the
  reason. Domain index builders (`mech/critique.py::build_index`, the arch index,
  the P&ID graph read) stop turning a read failure into an empty index. The two
  codes are **not** members of `CritiqueFocus` / `ALL_CRITIQUE_FOCUSES` (a
  `focus=None` run would otherwise warn about unknown focuses); they are values of
  `detail.code`, and `scan_incomplete` is the same word Task 10 uses as an error
  kind.
- **"Incomplete" is testable:** a cheap entity count per space taken before the
  read (`MAX_QA_ENTITIES`, default 2,000,000, refuses the read with
  `scan_incomplete` above it); on COM the export's record count is compared with
  the live counts of model and paper spaces; a mismatch is `scan_incomplete`.
- `EntityRecord` gains `visible: bool = True` (DXF group 60) for the validator's
  hidden-entity step. The validator's dimension lookalike step reads DXF type
  names from the snapshot, so COM's ActiveX names stop mattering.
- **Gates:** construction / duplicate / dimension-overlap / hidden findings at
  positions 1, 4,999, 5,000, 5,001, 10,001 and last, and on a paper layout; a check
  that raises yields `check_failed`; a 50,000-line critique finishes within a
  stated bound while a concurrent `system_status` answers within 0.5 s; matrix v7's
  zero-issue tasks (`mech_assembly`, `arch_roundtrip`, `pid_roundtrip`) stay at
  zero issues now that paper space is read.

### Task 3 — safe export cells (B03)

`engineering/export/cells.py` is the one serializer for every CSV and XLSX the
server writes (`pid/deliverables.py::write_csv`, `sheet/extract.py::write_rows`,
`understand/report.py::write_workbook`):

- each exporter declares its columns' kinds, `text` or `number`;
- **text** that begins with `=`, `+`, `-`, `@`, a tab or a carriage return gets a
  leading `'` in CSV; in XLSX every text cell is written as a string cell

## 5. W2 — identity, operations, verification engine

### Task 9 — document identity and the bound document (B11)

- **Identity:** every open document gets a `document_id` (uuid4 hex) when it is
  registered — not `$FINGERPRINTGUID`, which every template-born drawing shares,
  and not `$VERSIONGUID`, which every internal snapshot save rewrites. A
  `revision` counter starts at 0.
- **Revision = content revision.** ezdxf bumps it wherever the document's content
  changes: every point that sets `dirty`, undo, redo, `transaction_rollback`, a
  snapshot restore. Saving, exporting, finalizing and delivering do **not** bump it
  (a delivery manifest must not be stale the moment it is written). COM bumps it
  from the content-changing `ComBackend` methods themselves (a `_mutating`
  decorator, bumping on success and on failure) — never from the tool's cost
  class, which counts save and deliver as mutations and which `cad_batch` steps
  bypass. Operator edits made in AutoCAD: probe the document's
  `ObjectAdded` / `ObjectModified` / `ObjectErased` events
  (`DispatchWithEvents`, drained with `PumpWaitingMessages` inside each `_run`)
  on the live seat first; if they are usable they bump the revision, and if not,
  the documentation says COM staleness rests on the entity fingerprints of Task 12.
- **Bound document on COM:** new / open / activate bind `(Name, FullName)` and the
  id. `_ensure_document_state` splits into **rebind** (after our own document
  operations, as today) and **guard** — run inside the same executor job as the
  call, before any document-touching work: if AutoCAD's active document is not the
  bound one, the call is refused with `ActiveDocumentChangedError`
  (`{ok: False, kind: "active_document_changed", bound, active}`), reads used as
  verification evidence included. `transaction_rollback` addresses the bound
  document. After `take_snapshot(<.dwg>)` opens and closes a file, the bound
  document is re-activated.
- **Reporting:** `document_identity()` on both backends
  (`{document_id, revision, name, path, backend}`); `system_status`,
  `drawing_info` and `document_list` carry the id and revision.

### Task 10 — operation records and the result taxonomy (B12)

- `backends/operations.py`: `OperationRecord` (`operation_id`, tool,
  `request_hash` = sha256 of the canonical JSON of tool + arguments, state,
  document id, revision before / after, started / ended, error kind) in a bounded
  in-memory journal. States: `committed`, `partial`, `failed`, `refused`,
  `quarantined`, `cancelled`, `unknown_commit` (a mutating call cancelled or timed
  out while its worker ran — Task 1's `call_outcomes`).
- Ids are minted in `AuditMiddleware` into a ContextVar; a call that re-enters the
  middleware (the search proxy's `call_tool`) reuses the id already set;
  `cad_batch` mints one per step (its steps skip the middleware); COM passes the id
  into its executor explicitly (`run_in_executor` does not copy context).
- **Client-supplied ids** (needed for the roadmap's T03 / T04 exit scenarios):
  `cad_batch(operation_id=…)` and an MCP request `_meta.operation_id` on any tool.
  Same id and same request hash → the recorded result comes back without running
  again (`replayed: true`), or `requires_reconcile` when the first run ended
  `unknown_commit`; same id with a different hash → refused `operation_conflict`.
  The journal is in memory: a restart forgets it, and the docstring says so (B13
  makes it durable in 1.8.0).
- `BATCH_ERROR_KINDS` gains `quarantined` (emitted today but undeclared),
  `stale_revision`, `active_document_changed`, `scan_incomplete`, `unknown_commit`,
  `timed_out`, `cancelled`, `operation_conflict`; refusals carry `operation_id`;
  `system_status` lists recent operations.

### Task 11 — RequirementSet and the shared verification types (B15 residue)

- `engineering/verification/types.py` defines, once, the types every later W2
  task uses: `Requirement`, `RequirementSet`, `FeatureSelector`, `FeatureRef`,
  `ObservedFeature` (line, circle, arc, ellipse, polyline with bulges, point;
  handle, `block_path`, space, approximation note), `ObservedGeometry` (features +
  declared and inferred units), `Binding`, `Measurement`, `AcceptanceItem`, and
  the status vocabulary (`pass`, `fail`, `unknown`, `unsupported`, `ambiguous`).
- A requirement: `id`; `quantity` (distance, radius, diameter, angle, count,
  absence, concentric, coincident, parallel, perpendicular, tangent, horizontal,
  vertical); `target` (`nominal`, `unit`, and `min` / `max` / `exact` for counts);
  `features` (selectors); `datum`; `provenance` (`explicit`, `derived`, `assumed`,
  `conflicting`, `unknown`, `raster_estimate`); `source` (document, page, view,
  label, region); `manufacturing_tolerance` (its own source, or null) kept apart
  from the numeric `verification_epsilon`.
- `drawing_preflight(requirements=…)` validates typed items and keeps accepting
  the legacy `dimensions` dict (read-only, reported as legacy); conflicting
  provenance is kept and reported, never collapsed to one value.
- Optional persistence: `drawing_plan(..., persist_requirements=True)` writes the
  set into an `ACADMCP_REQUIREMENTS` XRECORD (the layer-states pattern), so a
  reopened file carries its requirements.

### Task 12 — the change-preview contract (B14 residue)

- `engineering/changes/preview.py`: `ChangePreview` = document id, revision,
  preconditions, planned edits. A precondition is an **exact** fingerprint — a
  hash of the entity's raw DXF attributes, geometry and XDATA, read the same way
  at preview and at apply (not `diff.signature`, which rounds to 0.01 and leaves
  out colour, linetype, XDATA, ellipse axes, dimension values and MTEXT
  formatting).
- Previews: `cad_batch(dry_run=True)` (preconditions for the literal handles in
  handle parameters — entities a step creates have none, and `$refs` resolve
  late), `drawing_refine(dry_run=True)` (also when the score already meets the
  threshold — today it returns `threshold_met` before the dry-run branch),
  `text_find_replace(dry_run=True)` (its `before` rows), `pid_from_spec(dry_run=True)`
  (a region precondition: the fingerprints of the entities inside the routing
  region).
- Apply: the same tools take `expected_revision` and/or `preconditions`; any
  mismatch refuses with `stale_revision` and changes nothing; because batch steps
  run as separate locked calls, the revision is checked again after the apply
  and an interleaved change is reported.
- COM `text_find_replace` searches what the ezdxf engine searches: paper layouts,
  block definitions and attributes, not only model space.

### Task 13 — observed geometry (B16, B31)

- `EntityRecord` gains, with defaults so every existing reader is unchanged: a
  tilted-plane flag; ELLIPSE centre, major axis, ratio and parameters; SPLINE
  degree and points; HATCH loops (edges or polyline paths with bulges, flags,
  nesting depth via `_nesting_depths`); DIMENSION defpoints 1–5, measurement
  (`get_measurement()`), override text, dimstyle and DIMLFAC (override or style);
  the `ACADMCP_*` XDATA payloads (Task 14's feature tags).
- `engineering/verification/observe.py::observe(snapshot, *, explode_inserts=True)`
  builds `ObservedGeometry`. Exploded INSERT geometry carries `block_path` and
  lives **only** there, never in `Snapshot.records` — the diff, the takeoffs,
  `drawing_understand` and the v7 tasks keep their inputs. A circle under a
  non-uniform scale becomes an ellipse and says so; a mirrored insert reverses arc
  direction correctly; units come with the geometry (declared and inferred).
- `entity_get` returns HATCH loops and full DIMENSION fields on both engines (COM
  members probed live first); the capability that today declares
  `hatch_boundaries_not_reported` flips in both capability maps.
- Gate: a HATCH's loop area equals `analysis_measure_entity`'s area for the same
  handle (bulges, islands, nesting); a nested mirrored, non-uniformly scaled
  insert containing a circle; a tilted circle reported unsupported.

### Task 14 — feature binding and native dimensions (B17, B29)

- **Feature tags, per entity:** the mechanical generators write a small
  `ACADMCP_MECH` record (`{kind: "feature", part, feature, view}`) on every entity
  they create, in the same create call (no extra COM round trip per primitive).
  A copy carries its tag, so two candidates for one feature are visible — the
  ambiguity B17 must report. Primitives gain a `feature` field (default "");
  1.6 drawings without tags fall back to geometric selectors.
- `engineering/verification/binding.py::bind(requirements, observed, *, policy)`:
  selectors by handle, by feature tag, by arch element (`ACADMCP_ARCH_H`), by
  geometric predicate (type + size window + region), by DIMENSION. Every binding
  carries its candidates and the reason it chose one; two equal candidates give
  `ambiguous` with both — never a random pick; none gives `unknown`.
- **Native dimension binding:** a DIMENSION's defpoints are matched to feature
  points (ends, centres, quadrants) within the epsilon; the report keeps the
  geometric measurement, the dimension's own measurement and its displayed text
  separate, so a text override or a DIMLFAC that hides a mismatch is a finding.
- **Held-out evidence (B29):** a synthetic held-out set built by a generator
  family different from the development fixtures; the report gives eligible,
  attempted, accepted and abstained counts, precision and coverage with Wilson
  95 % intervals; target ≥ 98 % precision and ≥ 80 % coverage on the supported
  native subset; abstaining on everything does not meet it.

### Task 15 — evaluators, constraints and counts (B18, B19, B20)

`engineering/verification/measure.py::evaluate(requirement, bindings, observed)`
measures from CAD-read geometry only: distance (point–point, point–line,
line–line), radius, diameter, angle, concentric, coincident, parallel,
perpendicular, horizontal, vertical, tangent (line–circle, circle–circle, arc
continuity), counts (exact / at least / at most, in a region or a feature class)
and absence. Each returns value, unit, method, residual and status
(`pass` / `fail` / `unknown` / `unsupported` for splines and tilted planes).
Expected values in tests come from hand-computed analytic oracles, never from
the generator; degenerate and near-tangent cases are explicit; metamorphic tests
(translate, rotate, mirror, mm ↔ inch on drawing and requirement together) keep
the verdicts. `point_intersection` additionally reports whether the point lies on
both segments.

### Task 16 — acceptance report and `drawing_verify_requirements` (B22, F02)

- `engineering/verification/report.py`: JSON (`schema_version: 1`) and Markdown;
  one row per requirement (target, measured, delta, tolerance basis, status,
  handles, source); denominators for required / pass / fail / unknown /
  unsupported / ambiguous; evidence marked stale when the document revision moved
  after it was measured. A missing requirement is never `pass`.
- New tool `drawing_verify_requirements(requirements=None, use_stored=False,
  binding_policy="strict", artifact_path=None, manifest_path=None, report_path=None)`,
  core pack and lean profile, SECTION 26 (banner 4 → 5), aliases. With
  `manifest_path` it re-hashes a delivery's artifacts and reports `stale` when one
  changed (B23 made observable).
- `drawing_finalize(requirements=…)` and `drawing_deliver(requirements=…)` add
  `geometry_acceptance`, `drafting_quality` (today's score), `artifact_integrity`
  and `coverage`; `score` stays as it is. A failed or incomplete acceptance blocks
  delivery (`status: "failed_acceptance"`); a high drafting score cannot offset it.

### Task 17 — saved-artifact verification and delivery (B21, B23 residue)

- `engineering/verification/artifact.py::verify_artifact(path, requirements)`: a
  fresh read of the saved file (never the in-memory model), re-binding by feature
  tag, then by geometry when a save renumbered handles; ambiguous → `unknown`;
  every requirement re-measured; the before / after comparison in the report.
- Delivery parity becomes `diff_snapshots` + `block_signatures` over all spaces:
  zero changed, added or removed entities within the tolerance, plus the counts.
  Exporting no longer re-points the document on either engine: COM uses
  `Document.Export` (rename the upper-case `.DXF` it appends to the manifest's
  name; record the DXF version), ezdxf writes a copy without changing
  `doc.filename`; `drawing_save_as` keeps its re-pointing semantics. The
  validator's "saved" step checks the exported canonical DXF in the delivery
  context; the source document's path and saved flag go into the manifest.
- The manifest gains acceptance, document id and revision, the requirements hash
  and the report hash; `verify_manifest(path)` recomputes every hash; `_git_sha`
  reads the server package's own checkout and falls back to the version alone in
  a wheel.
