# v1.7.0 W2 — identity, operations, verification engine: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every document has an id and a content revision; COM refuses to write
into a document it was not bound to; every call leaves an operation record with
an honest state, and a client can retry with its own operation id; requirements
are typed; a change can be previewed and applied only if nothing moved; a
requirement is bound to the real feature, measured on CAD geometry, reported
pass / fail / unknown, and measured again on the saved file.

**Architecture:** Identity and revision in the backends; an in-memory operation
journal minted by middleware; the pure package `engineering/verification/`
(types → requirements → observe → binding → measure → report → artifact) over the
snapshot reader; `engineering/changes/preview.py` for exact preconditions; one
new core tool, `drawing_verify_requirements`. One new contract member,
`document_identity()`, on both engines.

**Tech Stack:** as W1. **Spec:** `docs/superpowers/specs/2026-10-24-v1.7.0-design.md`
§5, §7, §8.

**Drafted after W1 merged:** read the merged W1 code on `release/1.7.0` before
writing a task. Where this skeleton's Interfaces disagree with what W1 landed
(`call_outcomes`, `qa_snapshot`, `EntityRecord.visible`, `_async(readonly=)`),
the landed code wins and the deviation is recorded in the task.

## Global Constraints

The W1 plan's Global Constraints apply unchanged (branch base `release/1.7.0`,
`uv run --frozen`, `--basetemp=out/pytest/<key>`, commit identity and trailer,
known red, ruff, registration gates, live AutoCAD rules and COM pitfalls,
deviations, confidentiality, triage assignments from
`docs/analysis/backlog-1.7.0-triage.json`). In addition:

- **Exact numbers in tests come from analytic oracles** written in the test (hand
  geometry), never from the generator or module under test.
- **No silent pass:** a requirement with no binding, an ambiguous binding or an
  unsupported measurement is `unknown` / `ambiguous` / `unsupported`, never `pass`.
- **EntityRecord stays hashable and backward compatible:** new fields have
  defaults and are tuples (or `field(compare=False, hash=False)`); readers that
  ignore them see no change; `diff.signature` does not change.
- **Live probes in groups** are raw pywin32 probes on their own `Document` objects
  (never `ActiveDocument`, never `SendCommand`); code that drives `ComBackend`
  against the live seat runs only in the foundation (Tasks 9–11) and the final
  (Tasks 16–17).

## Review Focus

4. **The operator switches AutoCAD's active document between two calls.** The
   second mutating call is refused with `active_document_changed`; nothing is
   written into the newly active document. *(Task 9)*
5. **An entity edited between preview and apply** — through the server and
   directly in the document. Apply refuses with `stale_revision` and changes
   nothing. *(Task 12)*
6. **A circle inside a mirrored, non-uniformly scaled nested block.** Observed as
   an ellipse with the approximation note; a mirrored arc keeps its true sweep.
   *(Task 13)*
7. **Two identical holes where the requirement names one; a copied feature tag.**
   `ambiguous` with both candidates, never a pick. *(Task 14)*
8. **A dimension whose text says 40 over geometry that measures 42; a DIMLFAC of
   2.** The geometric value fails; the displayed text and the dimension's own
   measurement are reported separately. *(Tasks 14, 16)*
9. **A save that renumbers handles; an artifact edited after its manifest was
   written.** Re-binding by tag then geometry, `unknown` when ambiguous;
   `verify_manifest` reports `stale`. *(Task 17)*
