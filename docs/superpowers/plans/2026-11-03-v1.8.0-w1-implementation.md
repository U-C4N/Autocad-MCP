# v1.8.0 W1 — the trust foundation: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** lineweights mean what DXF says and the critique sees overrides; every error, on
every route, is one typed envelope that says what to do next; the operation journal
survives the process, saves are atomic, a reopened drawing continues its revision and a
damaged DXF can be recovered on request; on COM the server draws where it means to and a
raw command reports what it did; a polyline can be edited in place and mechanical
dimensions carry feature tags; a region screenshot really shows the region.

**Architecture:** two pure modules (`engineering/errors.py`, `backends/atomic_write.py`),
one store (`backends/journal_store.py`, a subclass of the existing `OperationJournal`), one
new contract member (`entity_set_vertices`), one changed contract member
(`view_screenshot`), a shared lineweight parser in `backends/base.py`, a new critique
focus, and COM changes confined to `_msp()`, `_safe_send_command` and their callers. No new
tool in W1.

**Tech Stack:** Python 3.12 (uv-managed), FastMCP 3.4.5, ezdxf 1.4.4, pywin32 (COM),
matplotlib 3.11.1, openpyxl 3.1.5, anyio 4.14.2, stdlib sqlite3, pytest 9.1.1 +
pytest-asyncio, ruff 0.16.1 — all through `python -m uv run --frozen`.

**Spec:** `docs/superpowers/specs/2026-11-03-v1.8.0-design.md` (§3 execution model, §4 W1,
§9 refusals / Review Focus / gates). Canonical source: the maintainer's `plan.md` (§3 W1,
§5, §8).
